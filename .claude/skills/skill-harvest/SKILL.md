# skill-harvest — 成功パターンのスキル化

## 前提条件

- `.claude/success-log.md` に**同種の手順の成功が3回以上**記録されていること
- 「同種の手順」の判断基準: トリガー条件・手順ステップ・検証方法がほぼ同一であること。
- ユーザーがスキル化の提案を承認していること（承認前に SKILL.md を作成しない）

## 手順

### 1. 成功実績の収集
- `.claude/success-log.md` から対象タスク種別のエントリを抽出する
- 各エントリの**手順要約・主要成果物のパス**を一次資料として手順を復元する
- 同一セッション内の実績であれば、会話履歴・STATE.md・`.claude/change-log.txt` で詳細を補完する
- **後方互換ガード**: 手順要約を持たない旧形式エントリは比較対象から除外する。復元可能な実績が3回未満になった場合はスキル化を中止し、その旨をユーザーに報告する

### 2. 共通パターンの抽出
3回以上の実施を比較し、次の3つに分離する:
- **毎回同じだった部分** → スキルの手順本体にする
- **毎回異なった部分** → プレースホルダ（`<入力>` など）にする
- **一部の回でだけ起きた問題と対処** → 「よくある失敗と回避策」の候補にする

### 3. 抽象化の型に沿って SKILL.md を書く
新規スキルは必ず次の**4項目**で構成する:

1. **トリガー条件** — どういう依頼・状況でこのスキルを使うか。「使わない場合」も併記し、frontmatter の `description` にも反映する
2. **手順ステップ** — 番号付きの実行手順。各ステップは完了を検証できる単位にする
3. **検証基準** — 各ステップおよび最終成果物の合否をどう判定するか（verifier に渡せる形で書く）
4. **よくある失敗と回避策** — 実施時に実際に起きた失敗と、その回避方法

### 4. 配置・検証・報告
- `.claude/skills/<スキル名>/SKILL.md` として作成する（スキル名は kebab-case）
- frontmatter には `name` と `description` を必ず含める
- 作成した SKILL.md は、下記「検証基準（skill-harvest 自体の成果物に対する）」を受け入れ基準として verifier 検証にかけ、`passed: true` を確認してから報告する（検証依頼はメインエージェントが行う）
- 報告にはファイルパス・トリガー条件・手順の概要を含める

## 検証基準（skill-harvest 自体の成果物に対する）

- 生成した SKILL.md だけを読んで、経緯を知らない第三者が同種タスクを再現できること
- 特定のファイルパス・固有名詞が、必然性なくハードコードされていないこと
- 4項目（トリガー条件・手順ステップ・検証基準・よくある失敗と回避策）がすべて揃っていること

## よくある失敗と回避策

- **失敗**: 1回分の作業ログをそのまま写してしまい、汎用性がない
  - 回避: 必ず3回分を比較し、差分をプレースホルダ化する
- **失敗**: トリガー条件が広すぎて無関係なタスクで発動する
  - 回避: description に「使わない場合」の例を明記する
- **失敗**: 検証基準が「うまく動くこと」のような曖昧な表現になる
  - 回避: verifier にそのまま渡して合否判定できる粒度まで具体化する
